# Inherited-state audit — 2026-05-19

Forensic audit of the repository at the point Pubky took it over from the original contractor (`francismars`). Findings here drive the v1.0.0 work plan; each item is an action target, not a permanent doc.

Inherited reference: tag `inherited/2026-05-19` on commit `ade409a` (merge of `wip/webdav-debug-20260305`).

## Top-10 must-fix before v1.0.0

1. **Critical** — Remove `generateMockLogs()` in `src/components/organisms/DashboardLogs/DashboardLogs.tsx`. Wire the real logs endpoint once it lands in pubky-core, or hide the tab until then.
2. **Critical** — Remove `MOCK_USERS_BY_INVITE` in `src/components/organisms/InvitesDialog/InvitesDialog.tsx`. Fetch real invite→user mappings via the new `GET /admin/signup_tokens` endpoint.
3. **Critical** — Implement `ServerControlDialog` restart/shutdown for real. Currently a `setTimeout` simulation. Blocked on `POST /admin/restart` (and a shutdown endpoint if we want one).
4. **High** — Add path-traversal validation in `src/app/api/webdav/utils.ts:buildDavPath()` — `..` segments are not rejected today. Defense in depth even if upstream blocks them.
5. **High** — Tighten Cloudflare token file mode in `entrypoint.sh`. Currently `chmod 666` (world-writable); should be `0600` for the token file and `0700` for the directory.
6. **High** — Add test coverage for API routes that are currently untested: `cloudflare-config/route.ts`, `server-config/route.ts`, `admin/generate_signup_token/route.ts`, plus `services/admin/admin.ts` and `services/webdav/webdav.ts`.
7. **High** — Add Origin/Referer check for state-changing verbs (POST/PUT/DELETE/PATCH) on `/api/admin/*` and `/api/webdav/*`. Next.js default same-origin is fine; explicit check is defense in depth.
8. **Medium** — Resolve port inconsistency: package.json scripts use 8080, Dockerfile `ENV PORT=3000`, README says 3000. Pick one (Umbrel docker-compose sets `PORT=8812` per service so it doesn't matter to Umbrel, but local dev / standalone docker should match).
9. **Medium** — Remove the 7 `console.log` calls from `src/hooks/user/useUserManagement.tsx` (lines 31, 38, 45, 55, 59, 66, 86). Use the existing `src/lib/server/logger.ts` if logging is needed, or strip them.
10. **Medium** — Add Cloudflare token format validation in `cloudflare-config/route.ts` before persisting (length + character class).

## Other findings

### Mocks (per status report, confirmed)

- **DashboardLogs** — fully mock (#1 above).
- **InvitesDialog** per-invite user mapping — fully mock (#2 above).
- **ServerControlDialog** restart/shutdown — fully mock (#3 above).
- **ConfigDialog** — view-only; edit/save tab is intentionally disabled. Needs `POST /admin/config` to ship.
- **`services/user/user.ts`** — comment notes "storage, file count, and status are mock data"; only pubkey is stored. Needs `GET /admin/users/{pubkey}/usage`.

### Corrections to status report

- **DisabledUsersManagement** — the inherited status report listed this as partial mock (count real, list mock). **Actually live** today: the dashboard fetches the list from a real `/users/disabled` admin endpoint. No mock remains. Confirm endpoint behavior under load.

### API proxy

- `src/app/api/admin/[...path]/route.ts` — joins all dynamic path segments unchecked. Document the upstream trust boundary; consider an explicit blocklist of admin paths the dashboard never needs to proxy.
- `src/app/api/webdav/utils.ts` — full WebDAV method set is exposed (PROPFIND, MKCOL, MOVE, COPY, DELETE, PUT, GET); no allowlist by intent. Fine for admin context, but document.
- All routes buffer responses fully (`await response.text()`). Acceptable for admin API, risky for large WebDAV reads — investigate streaming pass-through for large file downloads.
- No explicit body-size limit in the proxies. Next.js default ~1MB protects most, but WebDAV upload bodies can be much larger; verify behavior.

### Env-var safety

- All `process.env.*` reads are in server-only files (`src/app/api/**`, `src/lib/server/**`). No `NEXT_PUBLIC_*` token leaks to the client. **No findings.**

### Docker / entrypoint

- Dockerfile correctly runs as non-root via `su-exec`. Multi-stage build, Next.js standalone output.
- **No `HEALTHCHECK`** — add one (e.g., `curl -f http://localhost:${PORT}/api/public-health || exit 1`). Umbrel reviewers expect it; we have an Umbrel-side healthcheck in docker-compose, but the image itself should also declare one.
- `entrypoint.sh` chmod modes are too permissive (see #5 above).

### Test coverage (baseline)

- 5 test files, 12 tests, all passing. Files covered: `route.ts` (admin proxy), `webdav/utils.ts`, `useAdminInfo`, `useDisabledUsers`, `useWebDav`. Status report's "zero tests" was stale.
- 54 source files total — ~9% file coverage. Untested high-value: `cloudflare-config`, `server-config`, `generate_signup_token`, `admin.ts` service, `webdav.ts` service, every organism component.
